# Mabinogi Mobile 日本版 DPS / Damage Lab v5.1

**2026-11-03 / 非公式・検証用 / ソースコードのみ**

ブラウザ不要の Tkinter GUI を追加した版です。旧 `jp_dps.py` と `jp_meter.html` を維持し、辞書CSVを利用した日本語名の表示を追加しています。

## 起動（Windows / PowerShell）

ZIPを `C:\Users\torah\repository\Mobinogi_Meter` 内に展開した場合：

```powershell
cd C:\Users\torah\repository\Mobinogi_Meter
.\.venv\Scripts\python.exe .\start_gui.py
```

または `start_gui.bat` をダブルクリック。既存の `.venv` があれば `pythonw.exe` でGUIを起動します。見えないエラーを調べるときは PowerShell から上のコマンドで起動してください。

- **通常のGUI起動・オフライン再生はPython標準ライブラリのTkinterだけ**で動きます。TkinterがPythonインストールに含まれている必要があります。
- **ライブ取得には `scapy` + Windows `Npcap` が必要**です。以前のv4.1で動いていた環境ならそのまま利用できます。
- `websockets` は旧ブラウザ版を使うときのみ必要です。GUIはWebSocketポートを開かず、UIへ直接イベントを渡します。
- Python 3.10以上を推奨します。

## GUI機能

1. NICの一覧取得・選択、パッシブなライブ計測の開始・停止。
2. PCAPNGを読み込み、1/3/10/30倍速または即時でオフライン再生。
3. 攻撃者別の累計ダメージ・平均DPS・直近5秒DPS・クリ率。
4. スキル別（派生別）または基本スキルにまとめたダメージ集計、追加攻撃回数。
5. 3種類のCSVを読み込んだ日本語名辞書の検索と、根拠・内部名の確認。
6. 全イベントCSV保存（UTF-8 BOM付きでExcelでも開きやすい）。
7. 選択した攻撃者に **手動で表示名を付ける**機能（キャラクター名の自動同定ではありません）。
8. **自動終了・自動リセットはありません**。何秒無通信でも累計を消しません。「集計をリセット」でのみ削除します。

## スキルCSV（提供ファイル3種類を同梱）

| ファイル | データ行数 | 用途 |
|---|---:|---|
| `data/mabi_player_skill_base_20261103.csv` | 274 | 基本スキル |
| `data/mabi_player_skill_candidates_20261103.csv` | 902 | 段数・派生を含むプレイヤー攻撃候補 |
| `data/mabi_skill_id_dictionary_jp_candidates_20261103.csv` | 8,189 | その他のスキル・内部処理を含む全候補 |

3ファイルは重複IDを含みます。パーサーが受信した `effect_id` に対し `numeric_id_hex` を引いて、日本語名候補と根拠（「実戦照合」「名称推定」「仮訳」など）を表示しています。

例えば、`0x0B656FA2` = クリスタルエッジ1段目、`0x4DFF3831` = 2段目、`0x7E51D8A1` = 3段目、`0x2972020F` = クリスタルソード（いずれもカカシ実測）。`0x240EEC7C` = 冬の印は、CSVに候補名があるものの **英語内部名からの仮訳** なので確定名称とは見なさないでください。

CSV未収録の効果IDも消さずに `未分類 0x...` と表示します。

## DPS集計と注意点

- 累計ダメージ: 手動リセット以降に受信した有効ダメージの合計。
- 平均DPS: 当該攻撃者の最初の有効ヒットから最後の有効ヒットの時刻差（最低1秒）で計算。無攻撃が続いても、その間は値を維持。再開時は空白期間も含みます。
- 直近5秒DPS: 最後の5秒間の有効ダメージ合計÷5。ライブ時は現在時刻、リプレイ終了時は最後の記録時刻を基準にします。
- クリ率: 有効ヒットのうち `crit` フラグが立った割合。DoT・追加ヒットを含み、ゲーム内の正式なクリ率と一致しません。
- `0xFFFFFFFF` はユーザー実戦確認による「敵の無敵状態での攻撃結果」。有効ダメージには足しません。
- **他人の攻撃アクションが届いても、他人のダメージ数値が届いているとは限りません。** 表は実際に取得できたダメージのみ表示します。
- ペット/DoT/一部ダメージレコードの未対応・重複・取りこぼしは未検証です。
- 自分のキャラ名はパケットの攻撃者IDから直接確定していません。表示名は手動指定です。
- ゲームサービスの利用規約上、非公認ツール利用による制限リスクがあります。安全・無BANを保証できません。

## v5.1 (2026-11-03) 追加修正

- **ブレイクエクステンド検出**: `0x5243(ダメージ)` → `0x5241(29Bの追加戦闘結果)` → `0x4FF7(効果ID)` の並びを解析できるようにしました。これまで効果IDなしになっていた **196,729ダメージ** から `0x46DDC8DC` を取得し、既存CSVの `IceMage_BreakExtend` に照合。GUI名は「アイシクルシャックル（ブレイクエクステンド）」です。`0x5241` の厳密な意味は未確定です。
- **火傷DoT分類**: 効果IDが `0x00000000`、かつ `dot=1`、`fire=1` のダメージを「火傷DoT（発生源未特定）」と表示します。観測データでは「凍りついた炎」ルーンによるものと実戦確認済みですが、**ルーンIDを直接取得できたわけではない**ため、同じフラグの別の火傷も含み得ます。
- **CSV強化**: `fire`, `break`, `flag_hex`, `effect_linkage`, `flag_byte4_bit0x20_candidate` 列を末尾に追加しました。`effect_linkage` が `via_0x5241` なら中間レコード経由で効果IDと対応したことを表します。既存CSV列はそのまま保持します。
- **自動リセットなし**: v5と同様、手動リセットまで累積を保持します。

実機ライブは未確認。オフラインでPCAPNGを使った確認と自動テストを行っています。非公式の受信専用ツールであり、運営の利用制限リスクがなくなるわけではありません。

- **新たなフラグ候補（未確定）**: `IceMage_BreakExtend` の1ヒットでは、flags[4] に `0x20` が立っていました。従来のカカシ108ヒット中は0件でしたが、**1例だけなので意味は未確定**です。これを `flag_byte4_bit0x20_candidate` に生値のビット有無として出力します。v5.1はこのビットだけでスキルを決めません。
